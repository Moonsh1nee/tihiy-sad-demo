# Тихий сад

Законченный демонстрационный интернет-магазин вымышленной цветочной мастерской в Волгограде. Next.js App Router, TypeScript, React, статический экспорт для GitHub Pages. Собственного backend нет.

**Демо-магазин: заказы и оплата не принимаются.** В каталоге нет реальных контактов, адресов, реквизитов и отзывов. Фотографии созданы встроенным ImageGen специально для проекта.

## Запуск

Node.js 24, npm. Зависимости и lockfile включены.

```sh
npm ci
npm run dev
```

Открыть [локальный магазин](http://localhost:3017/tihiy-sad-demo/). `npm run dev` предназначен для разработки. Проверять GitHub Pages нужно на production-экспорте:

```sh
npm run typecheck
npm run lint
npm test
npm run build
npm run preview
```

`preview` раздаёт именно `out` в подпапке `/tihiy-sad-demo/`, возвращает настоящую страницу 404 и не использует Next.js-сервер. Порт 3017; можно изменить через `PORT`.

Браузерные проверки запускаются после сборки:

```sh
npx playwright install chromium
npm run test:e2e
```

Playwright сам запускает статический сервер или использует уже работающий. Два профиля: 1440 × 1000 и 375 × 812, дополнительная проверка 320 px. Clipboard API не используется. Персональные данные не попадают в localStorage, URL, сетевые запросы или аналитику.

## Покупательский путь

Главная → каталог с фильтрами и сортировкой → карточка с галереей, размером, упаковкой и открыткой → корзина → данные и получение → проверка состава и стоимости → явное завершение демонстрации без заказа и оплаты.

- 12 разных букетов; у «Между строк» и «Тёплого персика» три фотографии, включая кадр в руках.
- Размеры S/M/L: 80/100/140% базовой стоимости. Пудровая бумага +150 ₽; открытка +100 ₽. Все суммы в целых копейках.
- Самовывоз в учебном сценарии бесплатный, доставка — 450 ₽. Временные интервалы ничего не бронируют.
- Одинаковые варианты объединяются. Размер, упаковка и наличие открытки различают позиции. Максимум 20 штук одного варианта.
- Восстановление корзины проверяет товары, варианты и количество, отбрасывает посторонние поля и пересчитывает цены. При отказе Storage API покупки работают в текущей вкладке до перезагрузки.
- Форма хранится только в памяти. После завершения очищаются данные и корзина; обновление страницы оформления также сбрасывает введённые данные.
- Каталог поддерживает поиск по названию и составу, быстрые подборки по поводу и избранное. Избранное доступно до перезагрузки страницы и не записывается в localStorage. Боковых корзин и модальных окон нет; мобильное меню доступно с клавиатуры и закрывается Escape с возвратом фокуса.

## Структура и решения

| Файлы                   | Ответственность                                                                           |
| ----------------------- | ----------------------------------------------------------------------------------------- |
| `src/lib/catalog.ts`    | Каталог, типы, пути локальных ресурсов, форматирование цены                               |
| `src/lib/shop.ts`       | Чистые функции вариантов, расчётов, восстановления и валидации                            |
| `src/lib/cart-store.ts` | Внешнее хранилище корзины для `useSyncExternalStore`, перехват ошибок Storage API         |
| `src/components/`       | Интерактивные части магазина                                                              |
| `src/app/`              | Маршруты, статические страницы, metadata и noindex                                        |
| `public/images/`        | Готовая локальная съёмка: WebP 400/640/1120 px и Open Graph JPG                           |
| `scripts/`              | Манифест, подготовка экспорта, статический сервер, необязательная оптимизация изображений |
| `tests/`                | Модульные и браузерные тесты                                                              |

Маршруты товаров перечислены через `generateStaticParams`, `dynamicParams = false`. Все страницы генерируются при сборке. `next/image` с серверной оптимизацией не используется: готовые WebP подключаются с `srcset`, `sizes`, ленивой загрузкой; первое изображение имеет высокий приоритет. Шрифты Cormorant Garamond и Manrope поставляются локально через Fontsource, без запроса к Google Fonts.

`postbuild` материализует dotted-файлы RSC-сегментов, если Next.js на Windows экспортировал их вложенными директориями. Это исправляет сам артефакт; локальный сервер не делает подмены маршрутов. На системах, где такие файлы уже существуют, скрипт их не меняет.

Генерация изображений описана в [docs/IMAGE-GENERATION.md](docs/IMAGE-GENERATION.md). Повторная генерация не нужна для сборки. Дизайн и план: [docs/PLAN.md](docs/PLAN.md). Результаты проверок: [docs/QA.md](docs/QA.md).

## GitHub Pages

Workflow: `.github/workflows/deploy.yml`. Публикация запускается при push в `main` и вручную через **Actions → Check and deploy to GitHub Pages → Run workflow**.

1. Создайте GitHub-репозиторий, например `tihiy-sad-demo`, и загрузите содержимое этой папки в ветку `main`, включая скрытую `.github` и `package-lock.json`. Не загружайте `node_modules` и `out` вручную.
2. Откройте **Settings → Pages → Build and deployment → Source: GitHub Actions**. Разрешите GitHub Actions в репозитории, если они отключены политикой аккаунта.
3. Дождитесь успешного задания `build`, затем `deploy`. Workflow выполняет `npm ci`, проверку типов, ESLint, Vitest, production-сборку и Playwright на собранном `out`. При ошибке проверок деплой не запускается.
4. Откройте адрес из environment **github-pages**. Для project Pages он будет `https://<username>.github.io/<repository>/`.
5. Проверьте опубликованные `/catalog/`, `/bouquets/01/`, `/cart/`, прямое открытие и обновление вложенного URL, фотографии/шрифты, неизвестный путь и полный путь до демо-итога.

Workflow использует официальные `actions/upload-pages-artifact` и `actions/deploy-pages`, `GITHUB_TOKEN` и OIDC; персональный токен не нужен. `contents: read` у сборки, `pages: write` и `id-token: write` только у публикации. Environment — `github-pages`, concurrency — `pages` с отменой устаревшего запуска. Артефакт — `out`.

### Переменные

| Переменная                | Значение                                                                                                         |
| ------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `NEXT_PUBLIC_BASE_PATH`   | `/имя-репозитория`. По умолчанию `/tihiy-sad-demo`; в Actions вычисляется автоматически из имени репозитория     |
| `SITE_ORIGIN`             | Origin без подпапки, например `https://username.github.io`; Actions подставляет его автоматически для Open Graph |
| `PORT`                    | Порт preview; по умолчанию 3017                                                                                  |
| `NEXT_TELEMETRY_DISABLED` | `1` отключает телеметрию сборки Next.js; в Actions установлено                                                   |

Секреты и ключи для демо не требуются. Переменные `NEXT_PUBLIC_*` доступны посетителю и не должны содержать секреты. Манифест генерируется при сборке с тем же basePath. Все ссылки и локальные ресурсы учитывают подпапку. Для root Pages репозитория `<username>.github.io` передайте пустой `NEXT_PUBLIC_BASE_PATH` и скорректируйте workflow; текущий workflow рассчитан на project Pages.

PowerShell, если репозиторий называется иначе:

```powershell
$env:NEXT_PUBLIC_BASE_PATH = '/flowers-demo'
$env:SITE_ORIGIN = 'https://username.github.io'
npm run build
npm run preview
# http://localhost:3017/flowers-demo/
```

В локальной среде без `SITE_ORIGIN` используется технический `https://example.invalid` для абсолютных OG-URL. Перед публикацией workflow автоматически заменит его корректным origin.

**Репозиторий:** [Moonsh1nee/tihiy-sad-demo](https://github.com/Moonsh1nee/tihiy-sad-demo). Адрес Pages после успешного развёртывания — `https://moonsh1nee.github.io/tihiy-sad-demo/`. Workflow подготовлен; успешная локальная сборка не считается подтверждением публикации. Для первого запуска выберите **Settings → Pages → Source: GitHub Actions** и проверьте завершение Actions и доступность страниц.

На всех страницах включая 404 установлен `noindex, nofollow`. Это требование нужно сохранить и на втором демо, на которое ссылается основной webakimov.ru. Основной сайт этот проект не изменяет.

## Что потребуется настоящему бизнесу

1. Реальный каталог, собственная предметная съёмка и система управления ассортиментом/остатками, сезонными заменами и ценами.
2. Backend для создания заказов и безопасного хранения персональных данных; база данных, резервные копии, доступы сотрудников и журнал операций. Клиентская корзина не может быть источником истины о цене.
3. Реальные тарифы, зоны и интервалы доставки; адрес и часы самовывоза; интеграция с курьерами или собственный диспетчерский процесс.
4. Эквайринг с подтверждением платежа на сервере, webhooks, онлайн-касса и чеки. Отдельная обработка ошибок, отмен и возвратов.
5. Уведомления и подтверждение заказа для клиента и флориста: email/SMS/мессенджер через сервер, без секретов в клиенте.
6. Юридические сведения, оферта, политика обработки персональных данных, согласия, правила доставки и возврата; проверка применимых требований перед запуском.
7. Мониторинг ошибок, защита формы от злоупотреблений, ограничение запросов и, при необходимости, согласованная аналитика без персональных данных. Домен и production metadata. Снять noindex можно только после перехода к реальному бизнесу; для демонстраций его сохранить.
